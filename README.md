# floorplan-3d-reconstruction

2D floor plan → wall-line extraction → 3D reconstruction pipeline.

**[▶ Live demo](https://zj0808.github.io/floorplan-3d-reconstruction/)** — the
extruded model rendered in the browser with Three.js. Drag to rotate, scroll to
zoom.

This repository is a **demo module sliced out of a private project**. The full
product (layout understanding, room segmentation, semantic reconstruction) stays
private for now; what is published here is the piece that matters for verifying
the approach: turning a raster floor plan into a clean set of axis-aligned wall
segments that a 3D extruder can consume.

## Why this exists

Most floor-plan images in the wild are messy: dimension lines, furniture icons,
text labels, hatching, door arcs. Feeding that straight into a 3D builder gives
you a soup of stray faces. The demo strips the image down to structural linework
first:

```
raw raster  →  binarize  →  morphological gap bridging  →  Canny edges
            →  HoughLinesP  →  axis-aligned snapping  →  dedupe  →  segments
```

The snapped + deduped segment set is what the 3D stage extrudes into walls.

## Pipeline stages

### 1. `line_extract.py` — 2D wall-line extraction

- Grayscale load, inverse binary threshold (walls are dark on light background).
- Morphological closing so broken wall lines caused by text overlays and
  dimension ticks merge back into one stroke.
- `Canny` edge detection, then `HoughLinesP` for probabilistic line segments.
- **Axis-aligned snapping**: real floor plans are overwhelmingly orthogonal, so
  near-vertical segments are collapsed to their mean `x` and near-horizontal ones
  to their mean `y`. This alone removes most of the "double wall" artefacts.
- **Dedupe**: segments within a tolerance of an existing one are dropped, since
  Hough fires many times on a single thick wall.

### 2. `reconstruct.py` — segments → 3D geometry

**Status: in progress.** The segment list is consumed here and turned into wall
quads by vertical extrusion. Current implementation sketches the contract
(segment in, wall mesh out) and the mesh writer; the wall-merging and
corner-joining logic is the open part.

### 3. Output

Extruded walls are emitted as an OBJ-compatible vertex/face list plus a plain
JSON dump of the wall graph, so the result can be inspected without a 3D
viewer.

## Usage

```bash
pip install -r requirements.txt

# inspect extracted segments (writes an annotated PNG)
python line_extract.py samples/plan_demo.png --debug

# segment -> 3D wall mesh
python reconstruct.py samples/plan_demo.png --height 2.8 --out out/
```

`line_extract.py` is also importable:

```python
from line_extract import extract_walls
segments = extract_walls("samples/plan_demo.png")
# -> [(x1, y1, x2, y2), ...]
```

## Roadmap

| Stage | Status |
|---|---|
| Wall-line extraction + snapping + dedupe | done |
| Segment → wall graph (topology, corner joining) | in progress |
| Wall mesh extrusion, OBJ + JSON export | skeleton in place |
| Room segmentation from the wall graph | pending |
| Semantics (doors, windows, fixtures) | pending |
| **3D reconstruction driven by Devin Bot** | planned — next milestone |

The 3D reconstruction stage is the one being built out with Devin Bot: Devin
gets the wall graph plus a target schema and produces the reconstruction plan,
which is then validated against the extracted geometry.

## Sample data

`samples/plan_demo.png` is generated by `samples/make_sample.py` — a synthetic
orthogonal floor plan with the usual noise (dimension ticks, two text labels, a
door arc, a furniture rectangle). No third-party plan images are used here.

```bash
python samples/make_sample.py
```

On this sample the extractor finds **12 segments (5 vertical, 7 horizontal, 0
diagonal)**:

```
$ python line_extract.py samples/plan_demo.png
12 segments (5 vertical, 7 horizontal, 0 diagonal)
(77, 82, 822, 82)      # top outer wall
(79, 622, 821, 622)    # bottom outer wall
(80, 651, 820, 651)    # dimension line, physically an outlier
(822, 79, 822, 621)    # right outer wall
(77, 81, 77, 619)      # left outer wall
(84, 462, 521, 462)    # partition, truncated by the door gap
(417, 357, 816, 357)   # horizontal divider
(417, 83, 417, 359)    # vertical divider
(559, 151, 761, 151)   # furniture rect, top
(559, 279, 761, 279)   # furniture rect, bottom
(559, 150, 559, 280)   # furniture rect, left
(761, 152, 761, 278)   # furniture rect, right
```

The last four are furniture, not structure, and the dimension line at
`y=651` sits outside the shell — both are expected at this stage. Filtering
them is part of the topology stage, not the extractor: the extractor's job is to
report linework faithfully, and deciding what is structural is a semantics
problem.

## Known issues / next

- **Furniture and dimension lines survive extraction.** On purpose — see above.
  The wall graph stage is where they get classified.
- **`cv2.imread` is not used.** OpenCV's path handling is ANSI-only on Windows,
  so the code reads through `np.fromfile` + `imdecode` instead; project folders
  with non-ASCII characters otherwise fail to load. Same for writing.
- **No wall thickness inference yet.** `--thickness` is a manual parameter. Real
  plans encode thickness as two parallel strokes; deriving it from the
  segment-pair distance is part of the topology work.
